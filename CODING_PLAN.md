# Bone Globle — Coding Plan

Companion to PLAN.md. This is the implementation plan: repo layout, data contracts,
pipeline, app modules, and milestones with acceptance checks.

## Verified facts the plan relies on

- **Data source**: BodyParts3D 4.0, `https://dbarchive.biosciencedbc.jp/data/bodyparts3d/LATEST/`
  - `isa_BP3D_4.0_obj_99.zip` (136 MB, 2,234 OBJs, 99% polygon-reduced, mm units, Z-up)
  - `isa_element_parts.txt`: concept `FMA5018` ("bone organ") lists exactly **203** bone mesh IDs
  - Each OBJ header carries `# English name : left patella` etc. Names are lowercase,
    laterality is a leading `left`/`right`, ordinals are words ("right second rib").
- **License**: official page (updated 2025-02) says **CC BY 4.0**. Required attribution string:
  "BodyParts3D, © The Database Center for Life Science licensed under CC Attribution 4.0 International".
- **Local tooling**: Node 24, npm 11, git, gh. No Blender, no Vercel CLI. Python 3.9 available.
- **Catalog draft**: `data/bone_catalog_draft.csv`, 120 answers (117 core + 3 optional
  ilium/ischium/pubis), covering 200 of 206 bones (ossicles excluded). Updated 2026-09-29:
  ossicles are catalogued as optional mesh-less entries and the hallux sesamoids are an answer.

## Data contracts

### `data/bone_catalog.json` (hand-maintained)

```json
{
  "slug": "rib-02",
  "displayName": "Second rib",
  "synonyms": ["rib 2", "2nd rib", "second rib", "true rib 2"],
  "region": "axial",
  "subregion": "thoracic-cage",
  "paired": true,
  "optional": false,
  "meshNames": ["right second rib", "left second rib"],
  "info": {
    "articulations": "...",
    "landmarks": "...",
    "fact": "..."
  }
}
```

`meshNames` must exactly match glTF node names. A test enforces: every catalog
meshName exists in the GLB, every one of the 203 GLB bones is either mapped to a
catalog entry or on an explicit ignore list (ossicles, sesamoids, sternum parts).

### `public/data/geometry.json` (generated by `05_derive.ts`)

```json
{
  "unit": "m",
  "bones": { "rib-02": { "centroids": [[x,y,z],[x,y,z]], "bboxCenter": [x,y,z], "radius": 0.05 } },
  "distance": { "rib-02": { "vertebra-t2": 0.041, ... } }
}
```

Distance between two answers = min over all (mesh of A, mesh of B) centroid pairs.
Also store `maxDistance` for color normalization. ~120x120 matrix, ~100 KB.

## Pipeline steps

1. `01_fetch.sh`: curl the zip and `isa_element_parts.txt`, `isa_parts_list_e.txt`,
   `partof_inclusion_relation_list.txt` into `data/bp3d/`.
2. `02_select_bones.sh`: awk FMA5018 rows -> 203 IDs -> `unzip -j` only those OBJs.
3. `03_build_glb.py` (python venv + trimesh): load each OBJ, read the English name from
   the header, scale mm->m, rotate Z-up->Y-up, center the whole skeleton at the origin,
   add to one Scene with `node_name = english name`, export `skeleton_raw.glb`.
4. `04_optimize.sh`: `npx @gltf-transform/cli` weld + simplify (if needed) + meshopt,
   with join disabled so per-bone nodes survive. Verify node count is still 203.
5. `05_derive.ts`: open the GLB with `@gltf-transform/core`, compute per-mesh centroids
   and bounds, join with the catalog, emit `geometry.json`. Fails loudly on any unmapped name.

Sternum: BodyParts3D splits it into manubrium/body/xiphoid. Catalog maps `sternum` to
all three mesh names. Hip bone: check whether it is one mesh or ilium/ischium/pubis;
the optional rows exist for that case.

## App architecture

- **State** (`game/state.ts`): a small reducer. `{ answer, guesses: Guess[], status: 'playing'|'won', gameId }`.
  Guess = `{ slug, distance, heat }`. Pure functions, unit-tested.
- **Search** (`data/search.ts`): build a flat index of `(term -> slug)` from displayName
  - synonyms, normalized (lowercase, strip punctuation, "2nd" -> "second"). Prefix match
    first, then fuzzy (small Levenshtein or a tiny lib like `fuse.js`). Already-guessed slugs
    shown but disabled.
- **Heat color** (`game/distance.ts`): `heat = 1 - clamp(d / maxDistance)`, mapped through a
  Globle-like ramp (cool grey-blue -> yellow -> orange -> red; exact match = bright green
  or white). Optionally gamma-adjust so nearby bones separate visually. Tuned in playtests.
- **Skeleton** (`three/Skeleton.tsx`): `useGLTF` -> traverse -> `Map<meshName, Mesh>`.
  Two materials: base (translucent bone-white, `transparent`, `opacity ~0.25`, `depthWrite false`)
  and per-guess opaque colored material (clone per guessed mesh). On state change, walk the
  guess list and assign colors; unguessed meshes keep the shared base material.
- **Camera** (`three/camera.ts`): OrbitControls with damping. On win, animate target and
  position to frame the answer meshes' bounding sphere.
- **UI**: header (title, help, stats), guess input pinned at top, guess list in a side panel
  on desktop / bottom sheet on mobile, win card overlay.
- **Random** (`game/random.ts`): uniform over non-optional slugs, excluding the last 10
  answers kept in localStorage.
- **Stats** (`game/stats.ts`): gamesPlayed, totalGuesses, per-slug `{ timesAnswer, totalGuessesWhenAnswer }`.
  StatsModal shows average and a "hardest bones" list.

## Milestones and acceptance checks

**M0 — Repo scaffold (30 min)**
Vite + React + TS, react-three-fiber, drei, vitest, eslint/prettier, `.gitignore`
(node_modules, dist, data/bp3d), MIT LICENSE, ATTRIBUTION.md, `git init`, first commit.
Check: `npm run dev` serves a blank page; `npm test` runs.

**M1 — Asset pipeline**
Steps 1-4 above produce `public/models/skeleton.glb` with 203 named nodes.
Check: a script prints node count and a sample of names; file size under 6 MB.

**M2 — Catalog + geometry**
Convert CSV to JSON, reconcile `meshNames` with actual GLB names (subagent task with the
name list in hand), run `05_derive.ts`.
Check: catalog integrity test passes (every meshName exists, every bone node accounted for).

**M3 — Viewer**
Skeleton renders, orbit works, base material translucent, a debug panel can color any
slug by name.
Check: on a mid laptop, 60 fps; loads in under 3 s on fast connection.

**M4 — Game loop**
Input, guessing, heat coloring, guess list, win detection, play again.
Check: play 5 complete games; every guess colors both sides; no crashes on repeats/unknowns.

**M5 — Win card content**
Draft `info` text for all 120 entries (subagent), you review. Win card and fly-to.
Check: spot-check 15 entries against a textbook.

**M6 — Polish + ship**
Help modal, stats modal, mobile layout, favicon, README, Vercel deploy from GitHub.
Check: Lighthouse performance > 80 on mobile; deployed URL plays end to end.

## Subagent delegation (Opus)

- Pipeline scripts (M1): one agent writes and runs steps 1-4, reports node names.
- Catalog reconciliation (M2): one agent maps 203 names to slugs, flags oddities.
- Info-card content (M5): one agent drafts, in batches by subregion, into the JSON.
- Viewer + game (M3/M4): built in the main session, since design decisions land here.

## Open risks

- 99%-reduced meshes look faceted up close. If unacceptable, swap source OBJs from the
  `olivercase/body_parts_3d_api` mirror (4.3, higher res, MIT scripts) at step 2; the
  rest of the pipeline is unchanged.
- Python 3.9 + trimesh: should work; fallback is doing OBJ->GLB in Node with
  `@gltf-transform/core` directly.
- Small bones (distal phalanges) may be nearly invisible when colored; consider a
  minimum on-screen highlight (outline or emissive glow) in M4 if playtests show it.
